# 卡 #9（失物招领）：安检 L2 可跑项（上线前档，本地能检的部分）
- 说明：L2 是"真机部署前必跑"，本卡在本地把**能检的全检掉**，不能本地检的（真实 TLS/云防火墙）标注"部署时验证"。
- 检查清单（产出追加到 `docs/pipeline/安检报告.md` 的 L2 段落）：
  1. **容器基线**：读 `Dockerfile`——基础镜像是否固定版本（禁 latest）、是否非 root 用户运行（无 USER 指令=加）、`.dockerignore` 是否排除 .env/.git；
  2. **认证端点限流**：登录/注册/send-sms 三个端点是否各自有**独立且更严**的限流（卡#3 装了全站基础限流；认证端点按 L2 标准应更严，如每分钟 5 次）——核实现状，缺失则给这三个端点加独立限流（复用 ratelimit 现成机制，key 加端点维度）；
  3. **日志脱敏审计**：grep 全部 logger 调用点，确认没有打印验证码/token/密码明文/完整手机号——发现即修（掩码化）；
  4. **HTTPS**：本地无 TLS，标注"部署时由反代层（nginx/caddy）终结，compose 现无反代服务=部署清单项"；
  5. **SBOM/制品签名/K8s/IaC**：标注"不适用（无对应基础设施）"；
  6. 依赖漏洞扫描：`pip-audit`（venv 内装临时用，不进 requirements）跑一遍后端依赖，高危项列出（只报告，升级与否留主程——防 breaking change）；
  7. CHANGELOG 记档。
- 验收（贴完整输出）：
  1. L2 清单逐项结论（通过/修复/标注不适用+证据）；
  2. 若加了认证端点限流：实测超频 429（贴输出）+ `pytest` 全量 0 failed（**串行单进程**贴统计+EXIT）；
  3. pip-audit 输出（高危项清单）；py_compile；git status 仅限清单；禁止 git 操作；命令逐个跑；失败 3 次停。
- 完成后输出：①L2 逐项结论表 ②验收输出 ③三句话总结。
