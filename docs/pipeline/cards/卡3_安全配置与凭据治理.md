# 卡 #3（失物招领）：安全配置与凭据治理（安检 L1 修复，P0）
- 背景：安检 L1 五项阻断——①JWT_SECRET 弱默认且 compose 未覆盖；②管理员工具码硬编码 "110"（config.py:137+前端 constants.ts）；③DEBUG=True 连坐：限流跳过（ratelimit.py:29）+验证码显示页面（一个开关拖垮两道防线）；④compose 将 MySQL 3306 映射宿主机+root 密码字面量 lf；⑤演示账号播种疑未门控（待核实 seed.py 是否有 Demo 账号）。
- 涉及文件：`app/core/config.py`、`app/core/ratelimit.py`、验证码显隐相关代码（先 grep 定位）、`docker-compose.yml`、`.env`（本机实际值）、`.env.example`（占位符）、`app/core/seed.py`（门控）、前端 `web/src/api/constants.ts` 与 mockAdapter（110 处理）、`CHANGELOG.md`。
- 实现要点（凭据纪律：所有密钥类值只从环境变量来，源码/示例/测试零字面量）：
  1. JWT_SECRET：默认值改空串+应用启动时校验"非空且非 dev- 前缀，否则 RuntimeError 拒绝启动"；本机 `.env` 写入随机生成的新密钥（`py -c "import secrets;print(secrets.token_hex(32))"`）；`.env.example` 只放 `JWT_SECRET=change-me-to-a-random-64hex` 占位；compose 加 `JWT_SECRET: ${JWT_SECRET:?请在.env设置JWT_SECRET}`；
  2. ADMIN_APPLY_CODE：默认改空串+启动校验（空=管理员工具禁用并在日志说明）；`.env` 本机可继续填 110（这是用户"好记"的明确需求，只是挪进环境变量不入库）；`.env.example` 占位；前端 constants.ts 的 MOCK_ADMIN_APPLY_CODE：先核实 mockAdapter 用途——若仅 dev mock 数据层则改读环境变量或在文件头注明"仅本地 mock，生产走真实接口"；若被生产代码引用则报告再动；
  3. **DEBUG 拆分（一个开关只管一件事）**：新增 `SHOW_SMS_CODE: bool = False`（演示显示验证码）与 `RATE_LIMIT_ENABLED: bool = True`；ratelimit.py 移除 `or settings.DEBUG`；验证码显隐代码改读 SHOW_SMS_CODE；本机 `.env`：`SHOW_SMS_CODE=True`（保留"家人自助注册"需求）+ `DEBUG=True` 保留（拆分后不再牵动安全）；`.env.example` 三个开关全列出并注释用途；
  4. compose：3306 映射改 `"127.0.0.1:3306:3306"`（仅本机调试可达）；`MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?请设置}`；DATABASE_URL 的密码段同样环境变量化；
  5. seed.py：核实是否有写死演示账号——有则加 `SEED_DEMO: bool = False` 门控（默认不播种），本机 .env 可开；没有则在报告记"指控不实"；
  6. 请求体大小护栏：核实 FastAPI/uvicorn 现状，无则加轻量中间件限制（如 2MB，按上传接口实际需要定），超限 413；
  7. 响应脱敏审计：核实用户序列化是否裸返手机号/邮箱——按"别人看你是脱敏（前3后4）、本人自查全量"原则处理；若牵扯前端展示逻辑改不动，写入安检报告"遗留项"并说明，不硬改；
  8. 密码哈希核查：确认注册/登录用 bcrypt/argon2——若 MD5/明文属阻断即修；已是 bcrypt 则报告记通过；
  9. 产出 `docs/pipeline/安检报告.md`：填 L1 第 1/2/3/5(CORS 已收敛记通过)/7(注入抽查)/8/9(仅交接码部分留给卡#4)/12 项结论+证据。
