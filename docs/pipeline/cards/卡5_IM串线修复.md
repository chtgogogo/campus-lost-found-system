# 卡 #5（失物招领）：IM 会话串线修复——第二个联系者不再拿到死会话（安检 P1 功能）
- 背景（im.py 约 120-128 行）：发起联系时"复用同一拾物下仍开启的会话"只按 `found_id + status==0` 查询，**没有过滤当前用户是否为该会话参与者**——第二个用户联系同一件失物时拿到第一个用户的会话，随后的参与者权限校验永远拒绝 → 403 死会话。
- 涉及文件：`app/routers/im.py`（发起会话处）、可能 `app/models/`（IMSession 字段核实）、`app/services/im_service.py`（若逻辑在 service）、相关测试、`docs/pipeline/安检报告.md`（功能缺陷记录）、`CHANGELOG.md`。
- 实现要点：
  1. **先读 IMSession 模型**确认双方参与者的字段名（如 lost_id/seeker_id 之类，以实际为准）；
  2. 复用查询加参与者维度：`found_id==X AND status==0 AND (参与者A==user.id OR 参与者B==user.id)`——自己与自己历史会话正常复用；查到**别人的**活跃会话时不复用，为当前用户新建独立会话（同一拾物允许多个一对一独立会话，语义=每个失主候选与拾得者各自一条私聊线）；
  3. 核实 IMSession 是否有 found_id 唯一约束/索引——有唯一约束则需迁移放开为 (found_id, 参与者) 组合唯一；无则直接生效；
  4. 测试：新增"第二个用户联系同一失物 → 获得自己的新会话且能正常发消息、原会话不受影响"；既有 IM 用例回归。
- 验收（必须实际执行并贴完整输出）：
  1. 双用户场景实测：用户A、B 先后联系同一失物 → A、B 各自拿到独立会话，各自发消息 200，互不可见对方会话（贴输出）；
  2. A 的旧会话继续可用（复用逻辑回归）；
  3. `pytest` 全量 0 failed（**串行单进程**，贴统计+EXIT）；
  4. py_compile 通过；git status 变更仅限清单。
- 禁止：不动消息读/写权限校验的其他逻辑；不重构 IM 整体设计（最小修复）；禁止 git commit/add。
- 完成后输出：①改动清单 ②双用户场景输出+全量测试 ③三句话总结。
