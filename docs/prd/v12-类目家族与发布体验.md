## 一、背景与问题

### 问题 1：自定义类目在匹配两端都漏（核心）

YOLO 系统类目 11 类 + 「其他」，但用户手填类目是自由文本。失主写「银行卡」、
拾主写「校园卡」时：

- **召回端**：`_recall_*_candidates` 只认「类目相等 ∪ 共享名词 tag」，两者皆不满足 → 候选都进不来；
- **打分端**：`_score_photo_category` 只有「相等 20 / 子串近似 10 / 不同 0」→ 直接 0 分。

类目是匹配的门槛维度，这里漏就是彻底漏。

### 问题 2：发布表单三栏重复

打分引擎 `_raw_text()` 把 title/description/appearance/features/location 拼成一整段
处理——「描述 / 外观 / 特征」三栏对引擎毫无区别，只对用户制造重复填写负担。

### 问题 3：用户不知道系统怎么理解自己的输入

描述写完直接发布，抽出了哪些标签、颜色/状态是否被识别，用户全程不可见，
录入了什么全凭运气。

## 二、方案

### 2.1 类目家族表（`app/services/category_service.py`，新增）

```
三级匹配：文字相等 20 分 → 同家族/歧义桥 15 分（新档）→ 子串近似 10 分 → 不同 0 分
```

- `CATEGORY_FAMILIES`：11 族 130+ 词（证件卡类/数码电子/钥匙类/雨具类/书籍文具/
  箱包类/钱包卡包/眼镜类/杯壶容器/衣物穿戴/玩偶饰品）。
- `AMBIGUOUS_BRIDGES`：歧义桥，「笔记本 ↔ 笔记本电脑」这类跨族真实歧义词对。
- 收词纪律：只收「同一件东西的邻近说法」，不收形态近但语义远的（书包 ∉ 钱包族）；
  单字泛称（包/卡/书）一律不收。
- **刻意不用向量语义**：中文短词向量阈值不稳、推理有成本、破坏黄金用例可复现性。

### 2.2 召回对称放行（`publish_service.py`）

`_recalled` 判定链追加一层：`类目相等 → 名词 tag 相交 → same_family()`。
注意家族判定**不依赖 noun_tags**（自定义类目恰常常名词标签为空）。

### 2.3 状态成色词扩充（`scoring_refs.py`）

- 成色词入「新旧」组：九成新/八成新/九五新 → 新侧；破旧 → 旧侧；
- 缺陷词入「完好/破损」组：磨损/划痕/掉漆/褪色 → 破损侧。
- 冲突语义保持组内反义判定：完好 vs 磨损 = 冲突（0 分 + 标记）；
  九成新 vs 磨损 = 不冲突（八成新的物品本就带磨损，判冲突会误伤）。

### 2.4 标签预览接口（`POST /api/v1/tags-preview`，新增）

复用 `TaggingService.extract`，与正式发布**同一套管线**，所见即所得；只读不落库。

### 2.5 发布表单重塑（`PublishView.vue`，重写）

- 颜色/成色改为**点选 chips**（15 色 × 10 成色/缺陷），点选词提交时并入描述前缀
  → 后端抽取管线零改动即命中；
- **智能确认卡片**：600ms 防抖调 tags-preview，实时展示「系统识别到的标签 +
  有遗漏可在描述补充」；
- 后端 `appearance`/`features` 列保留收空值，历史数据与 API 完全兼容；
- 表单字段收敛：拾物 6 项、失物 7 项（原 9~11 项）。

### 2.6 全局视觉令牌（`style.css`，重写）

- 主色 `#0f766e` 深青绿（避开默认蓝；信任/清爽语义）+ Element Plus 衍生色全套
  （light-3~9 / dark-2，否则按钮悬停仍是旧蓝，观感割裂）；
- 双层阴影（贴边 + 弥散）、毛玻璃 sticky 顶栏、页面入场 300ms 动画
  （`prefers-reduced-motion` 时关闭）、`:focus-visible` 焦点环、等宽数字。

**踩坑记录**：Element Plus `el-tag` 内置 `el-zoom-in-center` 过渡在部分内嵌/无头

先查过渡类名。v12 起标签类元素一律自绘样式，不依赖 EP 内置过渡。
