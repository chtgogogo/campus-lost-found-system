## 一、交付内容

### 1.1 API 限流（`app/core/ratelimit.py`，新增）

- **固定窗口计数器**（60s），复用 `redis_client.kv.incr`（Redis 优先、进程内存兜底），
  **零新依赖**（评审过 slowapi 方案，现有基建足够）。
- 超限抛既有 `RateLimitError`（HTTP 429）。
- **开关双保险**：`RATE_LIMIT_ENABLED=False` 或 `DEBUG=True` 时全放行——
  测试套件同 IP 高频注册登录，不豁免会全线误伤。
- 接入点与限额（`config.py`）：

| 接口 | 限额 | 维度 |
|---|---|---|
| POST /auth/register · /auth/login · /auth/send-sms | 10/分钟 | IP |
| POST /lost-items · /found-items | 10/分钟 | 用户 |
| POST /tags-preview | 30/分钟 | 用户 |
| POST /vision/predict | 30/分钟 | 用户 |

- 已知边界：反向代理后需改取 X-Forwarded-For（代码有注释）。

### 1.2 图片魔数校验（`app/utils/image_validator.py`，新增）

- **字节层判型**：JPEG/PNG/GIF/WEBP/BMP 五种魔数白名单；此前只看扩展名，
  `.html/.svg` 改名 `.png` 即可入库（SVG 是 XSS 载体）。
- 接线 `IMG_MAX_SIZE_MB`（config 定义已久但全库零引用的孤儿配置）→ 发布双入口
  （publish_lost / publish_found）+ vision/predict 统一校验。
- 伪造成 `.png` 的文本文件现在返回 HTTP 422「不是有效图片」。

### 1.3 词边界修复（`tagging_service.py` + `scoring_refs.py`）

| 问题 | 根因 | 修复 |
|---|---|---|
| 「图书馆」抽出假名词「书」 | 名词子串匹配不消费 | 地点**先抽并消费**，名词改消费式（钥匙串命中后不再拆钥匙） |
| 「校园卡」吞掉整句颜色 | CAMPUS_RE 把「…的校园」误判校区（潜伏 bug，评测集 P02 暴露） | `(?!卡)` 前瞻 + 前缀口语虚词黑名单 |
| 「学生食堂」vs「食堂」0 分 | 地点只做集合交集 | building 级增加跨侧包含判定 |
| 「无划痕」被当有划痕 | 状态词无否定语义 | 否定词(可隔「任何/明显」等填充词)+状态词整体匹配，否定不计入且整体消费 |

### 1.4 品牌冲突惩罚（`match_service._evaluate`）

评测证据（N03/N13）：失主 iPhone、拾主华为，其余全对齐 → 86.6 分误配。
现在：双方抽到品牌词且无交集 → `brand_conflict` 信号 + raw_total 扣 10 分。
信号同时进入 score_detail，前端可据此展示「品牌不同」提示。

### 1.5 匹配评测集（`evaluation/`，新增）

- `dataset.json`：**40 对人工标注样本**（20 正 / 20 负），刻意覆盖难点：
  同族不同词、歧义桥、品牌推断、同色不同物、同族不同卡、成色冲突、数量不符。
- `run_eval.py`：直接构造对象喂 `MatchService.score()`（无需 DB/视觉模型），
  输出 precision/recall/F1 + 逐对判定表 + 边界样本清单 → `results-v13.md`。
- **用法**：调任何权重/阈值后重跑 `python evaluation/run_eval.py`，前后对比即调优依据。

## 二、评测基线与修复效果

| 版本 | 精确率 | 召回率 | F1 | TP/FP/FN/TN |
|---|---|---|---|---|
| 修复前基线 | 71.4% | 50.0% | 58.8% | 10/4/10/16 |
| **v13 修复后** | **73.3%** | **55.0%** | **62.9%** | 11/4/9/16 |

**阈值扫描**（65/70/75/80/85）：最优 F1 在阈值 65（80%），但会放进 10 个负例——
正负分数带重叠严重，**降阈值是放水**；正确方向是继续增强判别信号。阈值维持 80。

**剩余误配（4 个 FP）均为文字天花板案例**，需照片维度（pHash/CLIP 精排已具备）区分：
- N01 同款不同物（黑伞无独有细节）——照片是唯一判据
- N05 全新 vs 破损——跨组冲突（成色组 vs 完好组）需成色等级制设计
- N06 一把 vs 两把——量词不符分值（8/15）当初用户拍板锁定，调升需重新拍板
- N07 银行卡 vs 身份证——同族不同卡，家族匹配的正确副作用

**剩余漏配（9 个 FN）集中在 70~80 分带**：前端已有 60~80「弱化疑似」展示带
（虚线卡片+低分确认文案），实际可达性优于二值指标。

## 四、遗留（v14 候选）

1. 成色等级制（1.0~0.2 数值化），解决全新↔破损跨组冲突（需先拍板等级表）；
2. 量词不符惩罚提升（8→10+，需重新拍板 U3 锁定值）；
3. 评测集扩到 100+ 对（当前 40 对，边界样本仅 6 条，统计功效有限）；
4. Redis 生产启用后限流自动跨进程生效（当前内存兜底仅单进程）。
