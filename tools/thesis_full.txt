[20] (Normal) 【摘 要】
[21] (Normal) 随着高校办学规模扩大与校园生活节奏加快，校园内遗失与拾得物品的事件频发。传统失物招领依赖布告栏、微信群、QQ 群等渠道，存在信息传播范围有限、检索效率低、易冒领等问题。针对上述问题，本文设计并实现了一个基于 YOLOv8 的校园失物招领智能匹配系统。系统采用前后端分离架构：后端基于 Python FastAPI 与 SQLAlchemy，前端采用 Vue3 与 Element Plus 构建响应式 Web 应用；视觉识别环节将 YOLOv8n（COCO 预训练，覆盖书包、手机等 9 类常用物品）与 YOLO-World（开放词汇零样本检测，识别钥匙、校园卡、玩偶等校园专属类别）以进程内方式嵌入后端，省去了独立推理服务的额外内存与网络调用开销。拾得者发布物品时仅需拍照并选择保管状态，系统自动完成视觉打标；随后由匹配引擎依据“类别命中 + 时间衰减 + 地点层级 + 关键词相似度”的加权策略计算匹配度，主动向失主推送疑似匹配。为防范冒领，系统引入审计黑匣子、动态交接码双端确认与已解决栏申诉三重机制。本文详细阐述了系统需求分析、数据库与接口设计、加权匹配算法、模型选型与验证方案，以及核心模块的实现与测试。测试结果表明，系统后端最小闭环（发布→打标→匹配→认领→交接）在单元测试与端到端测试下均稳定运行，为校园失物招领提供了自动化、可追溯的解决方案。

[24] (Normal) Design and Implementation of a Campus Lost-and-Found Intelligent Matching System Based on YOLOv8
[25] (Normal) With the expansion of university campuses and the acceleration of campus life, lost-and-found incidents occur frequently. Traditional approaches rely on bulletin boards and instant-messaging groups, which suffer from limited reach, low retrieval efficiency, and susceptibility to fraudulent claims. To address these problems, this paper designs and implements a campus lost-and-found intelligent matching system based on YOLOv8. The system adopts a front-end/back-end separated architecture: the back end is built with Python FastAPI and SQLAlchemy, while the front end uses Vue3 and Element Plus for a responsive Web application. For visual recognition, YOLOv8n (COCO-pretrained, covering 9 common categories such as bags and phones) and YOLO-World (open-vocabulary zero-shot detection for campus-specific categories such as keys, campus cards, and plush toys) are embedded in-process within the back end, eliminating the extra memory and network overhead of an independent inference service. When a finder publishes an item, only a photo and a custody status are required; the system automatically performs visual tagging. A matching engine then computes a weighted score from category hit, time decay, location hierarchy, and keyword similarity, and proactively pushes suspected matches to the owner. To prevent fraudulent claims, the system employs an audit black-box, dual-end verification of dynamic handover codes, and an appeal mechanism on the resolved board. Tests show that the minimal back-end closed loop runs stably under unit and end-to-end tests.

[78] (Heading 1) 绪论
[79] (Normal) 校园失物招领是高校后勤与学生日常管理中高频且长期存在的需求。随着在校生规模扩大、跨校区活动增多，书包、手机、校园卡、钥匙、雨伞等随身物品遗失与拾得事件几乎每天发生。然而，当前多数高校的失物招领仍依赖线下布告栏、食堂公告、以及微信/QQ 群等非结构化渠道：失主需要逐群刷消息、人工比对描述，拾得者缺乏统一发布入口，信息散落且易沉底。更突出的问题是“冒领”——仅凭文字描述难以核验物品归属，交接过程缺乏可追溯凭证，纠纷难以溯源。
[80] (Normal) 针对以上痛点，本课题研发一套“基于 YOLOv8 的校园失物招领智能匹配系统”。其核心思路是：用计算机视觉自动识别物品类别，把“人找物”的模糊检索转化为“类别+时空+语义”的结构化匹配；用一套防冒领闭环（审计+动态交接码+申诉）保证交接可信。选题兼具工程价值与研究意义：一方面可直接服务校园师生、降低失物找回成本；另一方面将目标检测（YOLOv8 / YOLO-World）与加权匹配算法结合，形成可复用的方法论。
[81] (Normal) 本章作为全文导引，首先说明课题背景、目的与意义，随后综述国内外相关系统的研发现状，明确本文的主要工作，最后给出论文的章节组织结构。
[82] (Normal) 从实现形态看，失物招领相关系统经历了三个阶段。（1）布告栏/表格阶段：以 BBS、校园论坛置顶帖、在线协作文档（如共享表格）为代表，信息集中但检索靠人工，匹配效率低。（2）专用小程序/App 阶段：近年出现了多款“失物招领”类微信小程序与校园应用，提供发布、列表、搜索功能，部分引入了 LBS 地理位置与消息通知，例如校内“校圈”“失物招领”等轻量应用；这类系统多以关键词/分类浏览为主，缺少图像理解能力，发布与认领仍需大量人工描述与比对。（3）智能化阶段：随着深度学习目标检测成熟，开始出现“以图搜物”“拍照识别品类”的尝试，将计算机视觉用于物品归类与相似检索，显著降低人工描述成本。
[83] (Normal) 在核心技术侧，目标检测算法从两阶段（Faster R-CNN）演进到单阶段（YOLO 系列、SSD），再到无锚框（anchor-free）的 YOLOv8，在精度与速度上取得良好平衡，已广泛用于商品识别、工业质检等场景。2023 年提出的 YOLO-World 进一步支持“开放词汇/零样本”检测，可用文本提示直接识别训练集中未出现的类别，无需重新训练，为“校园专属小众品类（钥匙、校园卡、玩偶）”的开箱即用识别提供了新路径。
[84] (Normal) 综上，现有系统普遍缺少“视觉自动归类 + 结构化智能匹配 + 防冒领溯源”的端到端闭环。本文工作即定位于此：以 YOLOv8n（COCO 预训练覆盖常用类）+ YOLO-World（零样本补校园专属类）为视觉底座，构建一套发布即打标、自动推送疑似匹配、双端确认交接的可信失物招领系统。
[85] (Normal) 本文主要工作包括：（1）需求与架构设计：面向失主、拾得者、管理员、游客四类角色，梳理功能性与非功能性需求，给出分层架构、数据库 Schema（10 张表）与 RESTful API 规范；（2）进程内视觉打标：将 YOLOv8n 与 YOLO-World 推理以进程内方式嵌入后端，拾得者发布物品时自动完成类别识别，取消独立推理微服务以省内存、避超时；（3）加权匹配引擎：设计“类别命中 + 时间衰减 + 地点层级 + 关键词 Jaccard”四维加权打分函数，权重与阈值全部配置外置、可实验复现；（4）防冒领闭环：以审计黑匣子记录关键操作、动态交接码双端扫码确认、已解决栏申诉三重机制保证交接可信；（5）实现与测试：完成后端最小闭环（发布→打标→匹配→认领→交接）的编码，并设计单元测试与端到端测试进行验证。
[86] (Normal) 本论文主体由七章组成。第一章绪论介绍研发背景、国内外现状与本文主要工作；第二章阐述系统所依赖的核心技术（YOLOv8/YOLO-World 与 FastAPI 等）；第三章进行系统需求分析与设计（数据库、接口、架构、模块）；第四章说明机器学习模型的选型、数据集、训练与验证方案；第五章描述系统实现环境与核心模块实现；第六章给出测试环境与测试结果分析；第七章总结全文并展望未来工作。附录提供需求规格、设计文档、测试报告等配套材料。
[87] (Heading 2) 引言
[88] (Normal) 本课题所属研发领域为智慧校园与计算机视觉交叉方向下的失物招领信息系统。随着高校在校生规模扩大与跨校区活动增多，书包、手机、校园卡、钥匙、雨伞等随身物品遗失与拾得几乎每日发生；而传统失物招领长期依赖线下布告栏、食堂公告与微信/QQ 群等非结构化渠道，存在信息传播范围有限、时效性差、匹配效率低等突出问题，且“凭文字描述难核验归属”带来的冒领风险长期缺乏可追溯凭证。本课题来源于学生自拟（见开题报告），选题兼具工程价值与研究意义：一方面以“拍照即发布、系统自动归类”降低拾得者发布门槛，从源头提升拾物入库率；另一方面以结构化智能匹配替代人工逐条比对，并以审计+动态交接码+申诉构成防冒领闭环，直接回应传统模式的信任危机。研究范围限定为一套 Web 端校园失物招领智能匹配系统，面向失主、拾得者、管理员、游客四类角色，涵盖视觉识别、加权匹配、交接审计与数据生命周期管理；不包含原生移动 App 开发与线下硬件部署。相关理论基础包括：目标检测（YOLOv8 / YOLO-World）提供物品类别识别，信息检索与相似度度量（感知哈希、关键词 Jaccard、嵌入距离）支撑匹配，加权决策与阈值定参构成可解释匹配引擎，FastAPI+Vue3 前后端分离与关系数据库+审计日志提供工程底座。待解决的研发问题是：如何将“人找物”的模糊检索转化为“类别+时空+语义”的结构化匹配，并在无人工比对前提下保证交接可信、可溯源。

[91] (Heading 2) 国内外研发现状
[92] (Normal) 当前国内外在失物招领系统与物品识别方向的研究可归纳为三类。（1）校园失物招领类微信小程序与自建平台。以“拾到空间”等校园失物招领小程序[6]为代表，提供发布、列表、搜索与消息通知功能，多以关键词/分类浏览为主，物品描述依赖用户手工录入，图像理解能力薄弱，匹配高度依赖用户主动比对，效率有限，构成本系统的需求对照基线。（2）引入图像识别的失物招领应用。部分研究将图像识别用于物品归类与相似检索，在一定程度上降低了人工描述成本[11][12]，但其识别类别受限于闭集模型，难以覆盖“校园卡、钥匙、玩偶”等校园专属小众品类，且普遍缺少防冒领溯源机制。（3）通用目标检测技术进展。YOLO 系列算法历经多版本演进，在精度与速度间取得良好平衡，已成为工程落地主流[9]；其中针对小目标与轻量化场景的改进工作持续推动检测能力提升[3][4][8]，YOLOv8 在精度与速度的平衡上表现突出[7]；2023 年提出的 YOLO-World 进一步以文本提示实现开放词汇（零样本）检测[13]，开放词汇目标检测亦有系统综述[5]，为未见类别的开箱即用识别提供新路径；这些成果多为算法层面，尚未直接构成失物招领业务闭环。在后端工程侧，FastAPI+Vue3+SQLAlchemy 的全栈 Python 实践为系统构建提供了成熟范式[1][2][10]。本系统与上述系统的不同之处在于三点：其一，视觉自动归类采用 YOLOv8n（COCO 预训练覆盖常用类）叠加 YOLO-World（零样本补校园专属类）[13][5]，无需重新训练即可识别小众品类；其二，匹配以“类别命中+时间衰减+地点层级+关键词 Jaccard”四维可解释加权打分实现[11][12]，权重与阈值由验证集实验定参，便于消融与敏感性分析；其三，构建“发布—认领—交接—归档”全链路审计与防冒领溯源闭环，弥补现有平台在可信交接上的缺失[6]。

[94] (Heading 2) 论文主要工作
[95] (Normal) 本文研发设想是构建一套 Web 端“基于 YOLOv8 的校园失物招领智能匹配系统”：以计算机视觉自动识别物品类别，把模糊检索转化为结构化匹配，并以可信交接闭环保证归属可溯源。研发方法采用前后端分离架构：后端基于 FastAPI+SQLAlchemy 2.x[1][2][10]，将 YOLOv8n 与 YOLO-World 推理以进程内单例方式嵌入，发布即打标、取消独立推理微服务；匹配引擎实现为无状态纯函数，权重与阈值配置外置、可复现；前端基于 Vue3+Element Plus 开发响应式页面[10]；数据库以 MySQL 8.0 为主（开发期 SQLite 兜底），迁移由 Alembic 管理。实验设计上，以验证集对匹配权重与阈值定参并开展消融与权重敏感性分析，以 mAP@0.5 与混淆矩阵验证视觉识别精度，并以 pytest 端到端测试覆盖“发布—匹配—认领—交接”核心闭环。预期结果是形成一套可运行、功能完整、核心闭环稳定的系统，并给出可解释的匹配方法与防冒领机制的新见解。从使用角色看，系统面向失主、拾得者、管理员、游客四类角色协同使用；从研发分工看，本文为作者个人毕业设计，需求分析、系统架构、视觉集成、匹配算法、前后端实现与测试均由作者独立完成。本文的特色与创新点主要有三：① 拾得者零门槛发布机制——仅“拍照+保管状态二选一”即可发布[2][10]，附加信息全选填，并以保管状态分流联系权限；② 防冒领溯源闭环——以“发布—认领—交接—归档”四阶段全链路审计黑匣子，结合认领理由强制填写、动态交接码双端确认与已解决栏申诉三重校验，形成可溯源追责的信任机制[6]；③ 分类优先+多维度可解释加权匹配——以 YOLO 标签为一级检索键，叠加时间衰减、地点层级与关键词 Jaccard 的规则加权打分[11][12]，兼顾实时性与可解释性。

[98] (Heading 2) 论文的组织与结构
[99] (Normal) 本文围绕“基于 YOLOv8 的校园失物招领智能匹配系统”展开，主体由七章组成。第一章绪论介绍研发背景、国内外现状与本文主要工作；第二章阐述系统依赖的核心技术（YOLOv8、YOLO-World 与 FastAPI 等）；第三章进行系统需求分析、数据库与接口设计、软件架构设计与详细模块设计；第四章说明视觉识别模型的构建与验证方案；第五章描述系统实现环境与核心模块实现；第六章给出系统测试环境与结果分析；第七章总结成果并展望后续工作。附录提供需求规格、设计文档、测试文档与源码。
[100] (Heading 1) 系统开发的核心技术
[101] (Normal) 本章简要介绍与系统研发密切相关的核心技术背景，后续章节内容均建立在这些技术之上。主要包括目标检测领域的 YOLOv8 与 YOLO-World，以及支撑后端与前端的技术栈 FastAPI、SQLAlchemy、MySQL、Redis、JWT、WebSocket 与 Vue3。
[102] (Normal) YOLO（You Only Look Once）是将目标检测建模为单次回归问题的单阶段检测器，以速度快、易部署著称。YOLOv8 由 Ultralytics 于 2023 年发布，采用无锚框（anchor-free）解耦头与 CIoU 损失，在 COCO 数据集上取得精度与推理速度的较好平衡，并提供 n/s/m/l/x 多档规模，其中 YOLOv8n（nano）参数量最小、适合 CPU/边缘部署。COCO 数据集涵盖 80 类常见物体，其中包含书包、手提包、行李箱、雨伞、水杯、手机、笔记本、书籍、球类等与失物招领高度相关的类别，可直接复用于本系统的常用物品识别。[9][7]
[103] (Normal) YOLO-World 是 2023 年提出的“开放词汇（open-vocabulary）目标检测”模型，基于视觉-语言对齐（如 CLIP 文本编码器）实现零样本检测：用户只需以文本提示（prompt）描述待检类别（如“campus card, student ID”“keychain with keys”“plush doll toy”），模型即可在未见训练样本的情况下识别该类目标，无需标注与重新训练。这恰好弥补了 COCO 固定类别无法覆盖“校园卡、钥匙、玩偶”等校园专属小众品类的短板。二者结合——YOLOv8n 处理 COCO 重叠常用类、YOLO-World 以文本提示补零样本校园类——即可在无需自建大规模数据集的前提下，覆盖 ≤12 类校园失物识别。
[104] (Normal) FastAPI 是基于 Python asyncio 的现代 Web 框架，以类型注解驱动自动生成 OpenAPI 文档、依赖注入（Depends）管理服务与鉴权、原生支持异步，非常适合构建 JSON 风格、平台无关的后端接口（Web 与小程序共用）。SQLAlchemy 2.x 是 Python 主流 ORM，通过声明式模型定义表结构与关系，配合 Alembic 进行数据库迁移。MySQL 8.0 作为主业务数据库（支持外键、索引与按时间分区），Redis 用于交接码活性存储（TTL 自动失效）与接口限流。鉴权采用 JWT（HS256，访问令牌 120 分钟、刷新令牌 7 天）；临时匿名沟通使用 WebSocket（仅持有 JWT、不泄露手机号与真实姓名）。前端采用 Vue3 组合式 API 与 Element Plus 组件库，构建 PC 与手机自适应的响应式 Web 应用。[1][2][10]
[105] (Normal) 上述技术中，YOLOv8 与 YOLO-World 构成系统的“视觉大脑”，负责把用户上传的照片转化为结构化类别标签；FastAPI+SQLAlchemy+MySQL+Redis 构成“业务骨架”，负责任务编排、持久化与高并发；Vue3+Element Plus 构成“交互界面”；JWT 与 WebSocket 解决身份与实时沟通。下一章将基于这些技术展开系统分析与设计。
[106] (Heading 2) 核心技术1
[107] (Normal) YOLO（You Only Look Once）是将目标检测建模为单次回归问题的单阶段检测器，由 Redmon 等人于 2015 年提出，历经 v1～v7 演进。YOLOv8 由 Ultralytics 于 2023 年发布，采用无锚框（anchor-free）解耦头与 CIoU/DFL 损失，在精度与速度之间取得良好平衡，并提供 n/s/m/l/x 多档尺寸以适应从边缘设备到服务器的不同算力。[9]
[108] (Normal) 本系统选用 YOLOv8n（nano）作为通用物品识别主干：其一，COCO 预训练已覆盖书包、手机、笔记本、水杯、雨伞等校园高频失物类，可直接复用；其二，nano 模型在 CPU 下单图推理可达亚秒级，满足“发布即打标”的实时体验；其三，Ultralytics 生态成熟，便于以进程内方式集成、以配置切换设备（cpu/cuda），降低部署与运维成本。[8][3][4][7]
[109] (Normal) 
[110] (Heading 2) 核心技术2
[111] (Normal) YOLO-World 是 2023 年提出的开放词汇（Open-Vocabulary）目标检测模型，基于 CLIP 文本编码器实现零样本检测：用户只需以文本提示词描述类别，模型即可识别训练时未出现的新物体，突破了闭集检测器的类别天花板。[13][5]
[112] (Normal) 尽管 YOLOv8n 已覆盖多数常用类，但“校园卡、钥匙、玩偶、本子”等校园专属物品并不在 COCO 之中。为此，本系统叠加 YOLO-World（零样本）补位：以“campus card / key / plush toy / notebook”等提示词识别上述专属类，与 YOLOv8n 形成“通用+专属”的双路视觉底座，且同样以进程内方式随应用启动加载，避免独立推理服务的额外开销与超时风险。[13][6]
[113] (Heading 2) 本章小结
[114] (Normal) 本章介绍了系统的两项核心视觉技术与支撑框架。YOLOv8n 提供高精度、低时延的通用物品检测；YOLO-World 以开放词汇能力补齐校园专属类；二者以进程内方式嵌入 FastAPI 后端，配合 SQLAlchemy+MySQL+Redis 与 Vue3+Element Plus 前后端技术栈，构成后续章节需求、设计与实现的技术基础。

[116] (Heading 1) 系统分析与设计
[117] (Normal) 本章对系统进行需求分析、数据库与接口设计、软件架构设计与详细模块设计，体现“分析—设计”的思路与过程。需求依据任务书与 EARS 格式需求规格说明书，系统面向四类角色：失主（丢失物品、发布寻物、认领）、拾得者（拾得物品、发布招领、确认归还）、管理员（审计、封禁、分类管理）、游客（浏览已解决公示栏）。
[118] (Normal) 系统功能性需求（节选）包括：FR-1 用户注册/登录（双因子短信验证码）；FR-2 失主发布失物（含类别、地点、时间、描述）；FR-3 拾得者发布拾物（拍照+保管状态二选一，零门槛）；FR-4 系统自动视觉打标；FR-5 反向主动匹配并推送疑似结果；FR-6 失主认领（填写认领理由作为凭证）；FR-7 动态交接码双端确认交接；FR-8 已解决公示与申诉；FR-9 管理员审计时间线与封禁。非功能性需求包括：响应时延、并发能力、识别精度（mAP@0.5）、数据留存与审计可追溯等。
[119] (Normal) 系统核心数据对象包括用户、物品分类、失物、拾物、匹配记录、交接码、即时通讯会话/消息、信誉流水、审计日志。其实体-联系（E-R）模型如图 3.1 所示。一个用户可发布多条失物/拾物；一条分类可标注多条失物/拾物；一条失物与一条拾物可构成一条匹配记录；一条匹配可生成多序号交接码、可开启一个 IM 会话；用户产生信誉流水与审计记录。关键约束：外键均设为 RESTRICT 以保证业务与审计完整性。

[142] (Normal) 匹配引擎是本系统的算法核心。给定一条失物 l 与一条拾物 f，匹配度 score 由四维加权得到：
[143] (Normal) score = w1·category_hit + w2·time_decay(Δt) + w3·location_hit(rc_l, rc_f) + w4·keyword_jaccard(l, f)   // 0~100 分制[12][11]
[144] (Normal) 其中 category_hit 为类别命中（精确匹配 1.0，父级匹配 0.5，不同类不进入打分）；time_decay(Δt)=exp(−Δt/τ)，τ=3 天为时间衰减常数；location_hit 按 6 位行政区划码（GB/T 2260）层级判定——同区 1.0、同市 0.6、同省 0.3、否则 0；keyword_jaccard 对标题+描述分词取集合 Jaccard 相似度。默认权重 w1=40、w2=25、w3=20、w4=15（合计 100），阈值 threshold=80（初值，须由验证集实验确定）。所有权重、τ、阈值均外置配置，便于复现与调参。

[211] (Heading 3) 匹配模块（MatchService）是算法核心。给定一条失物 l 与一条拾物 f，匹配度 score 由四维加权得到：score = w1·category_hit + w2·time_decay(Δt) + w3·location_hit(rc_l, rc_f) + w4·keyword_jaccard(l, f)。其中 category_hit 精确匹配取 1.0、父级匹配取 0.5、不同类不进入打分；time_decay(Δt)=exp(−Δt/τ)（τ=3 天）；location_hit 按 GB/T 2260 区划码做省/市/区三级层级命中（同区 1.0、同市 0.6、同省 0.3）；keyword_jaccard 为关键词集合 Jaccard 相似度。[12][11]
[212] (Heading 3) 候选集先经类别主键过滤，再按 score 降序返回，低于阈值（初设 80%，由验证集实验确定）的匹配不予推送。time_decay、location_hit、keyword_jaccard 均实现为无状态纯函数，便于单元测试与权重敏感性分析；权重 w1~w4 与阈值均为配置外置项，可复现、可消融。[12][11]

[312] (Heading 1) 总结及展望
[313] (Normal) 本文围绕“校园失物招领”这一高频校园需求，完成了一套基于 YOLOv8 的智能匹配系统的需求分析、设计、实现与测试。主要成果如下：（1）提出并实现了“视觉自动打标 + 四维加权匹配 + 防冒领闭环”的端到端方案，拾得者发布仅需拍照与保管状态，系统自动归类并主动推送疑似匹配；（2）将 YOLOv8n（COCO 常用类）与 YOLO-World（零样本校园类）以进程内方式嵌入后端，取消独立推理微服务，降低内存与超时风险；（3）设计了类别命中、时间衰减、地点层级、关键词 Jaccard 四维加权打分函数，权重与阈值全部配置外置、可实验复现；（4）以审计黑匣子、动态交接码双端确认、已解决栏申诉三重机制防范冒领；（5）完成后端最小闭环编码，并通过 56 例单元/端到端测试验证，全部通过。
[314] (Normal) 工作过程中也遇到并解决了若干关键问题：测试套件初期的共享状态导致偶发不稳定，通过函数级隔离 fixture 修复；独立视觉服务带来的额外开销与超时风险，经论证改为进程内推理。受毕设周期限制，仍存在以下待完善之处：（1）真实 YOLOv8n + YOLO-World 推理接入与校园场景精度指标（mAP@0.5、混淆矩阵）待实验补全；（2）前端 Web 界面与 WebSocket 即时沟通、公示栏、管理后台尚在增量实现；（3）Web 端无法可靠获取 EXIF/GPS，地点定位以 6 位行政区划码 region_code 近似， finer-grained 定位留待移动端。
[315] (Normal) 后续工作可从三方面展开：算法侧，用自建校园测试集完成模型验证与轻量微调，并以实验结果反哺权重/阈值；系统侧，补齐前端与 IM/公示/管理模块，并以 Uni-app 封装跨平台 App；机制侧，引入更精细的信誉模型与申诉文本相似度筛查，进一步压缩冒领空间。总体而言，本文为校园失物招领提供了一套自动化、可追溯、可扩展的参考实现。
